## 修复内容

`src/capture/` 提供可选的 RGBA16F 采集，再把线性 scRGB 转为原识别器使用的 BGR8。
不修改 Windows HDR、SDR 白电平或游戏显示设置，不放宽血条/角色模板的阈值。
默认读取安装目录的 `configs/capture-profile.json`；未配置时保留原采集。
`OK_WW_CAPTURE_PROFILE` 可指定另一个本地 JSON，作为显式覆盖。

配置格式：

```json
{
  "schema": 1,
  "mode": "calibrated_hdr_float",
  "reference_white": 2.75,
  "calibration_note": "2026-10-15 H27T22C 本机样本校准，模拟训练和日常领奖已实测"
}
```

2.75 是这台设备样本的实验校准值，不是通用 HDR 参数，也不是对系统亮度的修改。
线性参考白之外的高光仍会在最终输出时裁剪。正式启用前必须核对颜色、锁定、切人及结算，
不能以某张截图匹配分数提升替代通关验证。回退时将实际生效配置的 `mode` 改为
`legacy_bgra8`，或移走默认配置并清除环境覆盖，然后重启业务进程；仅清除环境变量不会关闭默认文件里的适配。

适配固定 `ok-script==2.0.8`，还核对实际 WGC 源文件指纹。底层源码有变化时拒绝启用，
需重新核对接口并测试。设备丢失/转换失败会报告错误，需重建采集对象或重启业务进程；
单纯 close/start 同一对象不会清除错误。不自动回退到前台采集或输入。
GUI、debug、web 和官方 CLI 都通过 `config.py` 注册同一适配。

## 防止覆盖

1. 2026-10-15 本机现用安装已通过 PyAppify 配置 API 设置 `MANUAL_UPDATE`。
2. 源码和修复保存在 Git 分支；不再把安装目录里的手改当作唯一副本。
3. 本分支移除业务程序里的官方启动器升级项，锁定框架依赖，禁止 fork 运行继承的
   Windows Release 流水线；这不等于修改现有启动器更新源，也不阻止用户手动覆盖。
4. `pyappify.yml` 仍是上游发布配置，**不能用于构建本分支安装包**。它指向官方更新仓库，
   源码仓库本身也不是可直接替换的发布仓库。
5. 正式分发还需要自有更新产物仓库、个人发布配置和流水线；构建时内联固定框架及本适配，
   再把启动器的更新源改为该发布仓库。当前原安装目录直接加载补丁并保持手动更新，不发布误指官方的安装器。
